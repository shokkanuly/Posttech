## 1. Обзор проекта

**JanaMen** — это модульный MVP для хакатона, объединяющее личный профиль сотрудника, кадровые заявки, обязательное обучение и доказательный AI-ассистент в едином удобном рабочем пространстве.

- **Frontend**: Адаптивное Single Page Application (SPA), созданное на базе чистого HTML5, современной дизайн-системы Vanilla CSS (фирменные цвета Jana Post, темная/светлая тема) и Vanilla JavaScript. Без тяжелых сторонних UI-фреймворков.
- **Backend**: Модульный монолит на FastAPI и SQLAlchemy 2.0 ORM с миграциями Alembic и строгим серверным контролем доступа (RBAC).
- **Безопасность и авторизация**: Серверная валидация прав доступа, безопасное хеширование паролей PBKDF2-HMAC и отзывные сессии на базе JWT Bearer токенов.
- **Движок кадровых заявок**: Транзакционное создание заявок (отпуск и аванс), проверка баланса дней, очередь согласования для руководителей и полный журнал истории изменений.
- **Jana Academy (LMS)**: Каталог курсов, просмотр уроков с поддержкой Markdown, интерактивное тестирование с мгновенной проверкой ответов и сохранением прогресса в базе данных.
- **AI Jana (Доказательный AI-ассистент)**: Точные выдержки из утвержденных HR-источников с реальными ссылками и безопасным фоллбэком. Демонстрационные источники явно помечены как синтетические; поиск не гарантирует понимание смысла вопроса.
- **Границы интеграции**: Документированные адаптеры (Mocked Boundary) для будущей бесшовной интеграции с **1С:ЗУП 3.1** и **Documentolog (ЭДО)**.

## 2. Локальный запуск и быстрая настройка

Проверено на Python 3.14 в macOS. Python 3.11 указан как целевая версия в конфигурации; Linux/Docker в этой сессии не запускались.

### Шаг 1: Виртуальное окружение и зависимости

```bash
# Перейдите в корневую директорию проекта
cd "/path/to/project"

# Создайте и активируйте виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate

# Установите зависимости
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
```

### Шаг 2: Настройка конфигурации и базы данных

```bash
# Переменные окружения для локальной демонстрации
export ENVIRONMENT=development
export DEMO_MODE=true
export DEMO_PASSWORD='Password123!'
export DATABASE_URL=sqlite:///./janamen-demo.db
export ACCESS_TOKEN_EXPIRE_MINUTES=60
export AI_CONFIDENCE_THRESHOLD=0.8
export ENABLE_MOCK_INTEGRATIONS=false

# Применение миграций схемы базы данных
python -m app.migrate

# Наполнение базы синтетическими демонстрационными данными
python -m app.seed
```

### Шаг 3: Запуск сервера разработки

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

- **Веб-интерфейс платформы**: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- **Интерактивная документация Swagger**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- **Документация ReDoc**: [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)

2. Сотрудник не может согласовать собственную заявку, а руководитель не имеет доступа к сотрудникам чужих отделов.

### Шаг 10: Телеметрия интеграций и аудит-лог

2. Откройте **HR-администрирование**.

## 8. Архитектурные границы интеграций

### 1. 1С:ЗУП (ЗУП 3.1 — Зарплата и управление персоналом)
- **Роль**: Мастер-система для учета кадров, оргструктуры и накопленного баланса отпусков.
- **Модель взаимодействия**: Чтение данных (Read-Only) через защищенный OData или REST HTTP-сервис.
- **Реализация**: `app/integrations/one_c_zup.py` возвращает статус UNCONNECTED. Реальные адреса API, учетные данные и синхронизация отсутствуют.

### 2. Documentolog (Система электронного документооборота)
- **Роль**: Регистрация кадровых приказов, маршрутизация на подписание ЭЦП и архивное хранение.
- **Планируемая модель**: REST-вызов после одобрения, только при наличии документации и согласованного подключения. Сейчас внешних вызовов нет.
- **Реализация**: `app/integrations/documentolog.py` возвращает UNCONNECTED; необязательная локальная симуляция присваивает MOCK-ID, без регистрации документа во внешней системе.

## 9. Границы и ограничения прототипа

1. **Внешние интеграции**: 1С:ЗУП и Documentolog не подключены. Нельзя считать локальный MOCK-ID официальной регистрацией.
2. **AI-модель**: AI Jana использует детерминированный поиск по ключевым словам и тегам утвержденных документов, что гарантирует работу в закрытом контуре без обращения к платным облачным API.
3. **Данные**: Все профили сотрудников, подразделения и документы являются синтетическими и созданы специально для демонстрации кейса Jana Post.

## Обновление backend и API

Применяйте `python -m app.migrate` к выбранной базе после резервного копирования. Новая миграция `0003_knowledge_revisions` добавляет счетчик редакций документов без удаления данных. Исходные `.env` и `janamen.db` при проверке не изменялись.

- [Контракт API](docs/API_CONTRACT.md), [все эндпоинты](docs/ENDPOINTS.md), [OpenAPI JSON](docs/openapi.json).
- Списки принимают `limit` (1–100, по умолчанию 50) и `offset` (0–1000000). Интерфейс загружает последующие страницы автоматически.
- Утверждение HR-источника требует `{"is_approved":true,"expected_revision":<revision>}`. После 409 нужно заново загрузить и проверить текст.
- Цитаты содержат `document_revision`; `/api/v1/ai/sources/1?revision=3` возвращает 409, если утвержденный источник изменился.
- `MAX_REQUEST_BODY_BYTES=262144` ограничивает размер тела запроса; превышение дает 413.
- Для отдельного frontend настройте `ALLOWED_ORIGINS` явным JSON-списком адресов. Стандартный интерфейс раздается тем же сервером и использует `/api/v1`.

```bash
python -m ruff check app tests migrations smoke_test.py dependency_audit.py
python -m ruff format --check app tests migrations smoke_test.py dependency_audit.py
python -m mypy app
python -m pip check
python dependency_audit.py --output docs/evidence/dependency-audit.json
# Сервер должен быть запущен; сценарий изменяет только выбранные демонстрационные данные:
JANAMEN_BASE_URL=http://127.0.0.1:8000 python smoke_test.py
```

Ограничения: один сервер/организация, SQLite, ограничение входа хранится в памяти процесса, нет SSO/сброса пароля/ротации refresh-токенов. Для внешнего доступа нужен HTTPS. Суммы авансов пока хранятся как Float и не используются для платежей. Старые тексты источников не архивируются; номер редакции предотвращает открытие нового текста под старой цитатой. Docker и другие ОС требуют отдельной проверки.
