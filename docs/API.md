# API JanaМен

Базовый путь: `/api/v1`, тела в JSON. Подробные схемы — в сгенерированном [docs/openapi.json](openapi.json) (на работающем сервере — `/openapi.json`, интерактивно — `/docs` и `/redoc`). Внутренний шлюз описан отдельно в [docs/gateway-openapi.json](gateway-openapi.json) и [docs/INTEGRATIONS.md](INTEGRATIONS.md).

48 операций на 45 путях. Для каждой операции в `tests/test_api_matrix.py` есть автотест успешного авторизованного вызова, а все защищённые операции дополнительно проверяются без токена, с отозванной, искажённой и деактивированной сессией. Тест `test_exported_openapi_matches_application` следит, чтобы `docs/openapi.json` совпадал с кодом.

## Общие правила

**Аутентификация.** Заголовок `Authorization: Bearer <token>`. Вход возвращает подписанный JWT с полями `sub`, `jti`, `iat`, `exp` и сохранённую сессию. Каждый защищённый запрос проверяет подпись, срок, активную сессию и активного пользователя; роль берётся из базы, а не из токена. Выход отзывает текущую сессию. Токен в браузере хранится только в памяти. Cookie-аутентификации и refresh-токенов нет.

**Идентификаторы.** Все ID в путях — целые числа от 1 до 9223372036854775807; в JSON ID и предусловия ревизий должны быть именно целыми (строки, дробные и логические значения отклоняются). Слишком большие ID получают 422 до обращения к базе.

**Размер запроса.** Тело ограничено `MAX_REQUEST_BODY_BYTES` (по умолчанию 262144 байта), включая потоковую передачу; превышение — 413 до разбора JSON, неверный `Content-Length` — 400.

**Списки и страницы.** `/requests`, `/manager/requests`, `/manager/team`, `/courses`, `/notifications`, `/admin/knowledge`, `/admin/knowledge/documents`, `/admin/audit`, `/ai/documents` принимают `limit=1..100` (по умолчанию 50) и `offset=0..1000000`. Ответ — массив; следующие страницы запрашиваются, пока страница не окажется короче `limit`. Заявки, уведомления и аудит отсортированы по убыванию времени создания и ID. Интерфейс подгружает страницы сам.

**Язык.** Заголовок `Accept-Language: ru-RU` или `kk-KZ` (принимается и `kz`), с учётом весов. Без поддерживаемого языка API отвечает на английском для совместимости. Ответы содержат `Content-Language` и `Vary: Accept-Language`. Переводятся тексты интерфейса и сообщения проверки; ключи JSON, роли, коды статусов и типов, ID, e-mail и текст пользователей не меняются. Язык никогда не влияет на права.

**Ошибки.** Для совместимости сохраняется строка `detail`, плюс `error: {code, message, fields}` и `request_id` (также в заголовке `X-Request-ID`). Ошибки полей содержат расположение и сообщение — без исходного ввода, учётных данных и текста базы. Коды: 401 — не аутентифицирован, 403 — нет прав, 404 — не найдено или чужая запись, 409 — недопустимый переход или конфликт уникальности, 413 — слишком большое тело, 422 — неверный ввод, 429 — слишком много попыток входа, 503 — база недоступна, 500 — непредвиденная ошибка. Все ответы содержат `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY`.

## Правила предметной области

**Заявки.** Код заявки выделяется из ID базы в отдельном пространстве `REQ-N…`, чтобы не пересекаться со старыми кодами. Даты — не раньше текущей даты в Алматы и не дальше `REQUEST_HORIZON_DAYS`. Отпуск считается в календарных днях: выходные списываются, государственные праздники РК и даты из `LEAVE_EXCLUDED_DATES` — нет. Дни в ожидающих заявках резервируются; пересечение с действующим отпуском — 409, нехватка дней с учётом резерва — 400. Одобрение выполняется условным обновлением из статуса «На рассмотрении» и в той же транзакции списывает дни, пишет историю, уведомление и аудит. Повторное или конкурирующее решение — 409. Аванс ограничен `MAX_ADVANCE_AMOUNT` и хранится только для процесса — выплаты нет.

**Обучение.** Результат — доля успешно пройденных уроков. Курс завершён, когда пройдены все уроки; уроки открываются по порядку. Просмотр каталога и назначение курса — разные действия. Сертификат в интерфейсе — демонстрационный, а не официальный документ.

**AI Jana.** Детерминированный поиск по точному тексту утверждённых источников без внешней модели по умолчанию. Источник должен покрывать значимые слова вопроса; повтор общих слов уверенность не повышает. Неподдерживаемые детали приводят к безопасному отказу, даже если общая тема есть. Ссылки содержат реальные ID и ревизии документов. Демо-документы помечены как синтетические, а не как официальные правила. В аудите — ID источников, статус ответа и хеш вопроса, без текста вопроса и ответа.

**База знаний.** У документа есть растущий номер `revision` (с 1); ответы по фрагментам содержат `document_revision`. Любое изменение метаданных, текста или утверждения увеличивает ревизию в той же транзакции. Изменения принимают необязательный `expected_revision`, устаревшее значение — 409 без изменений. **Утверждение требует `expected_revision`**, связывая его с тем текстом, который проверил HR, например: `PATCH /admin/knowledge/documents/1` с `{"is_approved": true, "expected_revision": 3}`. Переводы (`translations.ru`, `translations.kk`) проходят ту же проверку и утверждение, что и оригинал.

**Настройки.** В разработке можно использовать временный ключ подписи; в продакшене обязателен сильный секрет из окружения, демо-режим и наполнение демо-данными запрещены, кросс-доменный доступ — только для явно указанных адресов. Миграции применяются явно (`python -m app.migrate`); при запуске проверяется текущая ревизия, и при отсутствии миграций сервер останавливается с понятной подсказкой.
