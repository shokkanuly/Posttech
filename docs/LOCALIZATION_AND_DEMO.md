# Русский и казахский интерфейс, демо-аккаунты

Проверено 16 октября 2026 года. Существующий интерфейс HTML/CSS/JavaScript и модульный backend FastAPI сохранены. Сервер демонстрации: http://127.0.0.1:8765/. Используется отдельная временная SQLite-база; исходные `.env` и `janamen.db` не изменены.

## Учётные записи

Созданы последовательно: HR → руководитель → сотрудник. Все данные вымышленные.

| Роль | Электронная почта | Пароль локальной демонстрации |
|---|---|---|
| HR-администратор | `hr.demo@example.com` | `Password123!` |
| Руководитель | `manager.demo@example.com` | `Password123!` |
| Сотрудник | `employee.demo@example.com` | `Password123!` |

Сотрудник подчинён именно этому руководителю и назначен на два курса. При создании баланс — 24 дня. В проверочной базе однодневная заявка `REQ-N000007` согласована руководителем; остаток сотрудника — 23 дня. Первый урок пройден; прогресс первого курса — 25%. Пароли не возвращаются публичным API, переключатель роли не даёт прав без входа.

`python -m app.provision_demo` использует `DEMO_PASSWORD`, требует `DEMO_MODE=true` и непромышленное окружение. Повторный запуск не сбрасывает пароль и не создаёт повторных назначений. Несовпадение существующей роли, профиля или руководителя останавливает операцию вместо перезаписи. Каждая учётная запись с профилем сохраняется отдельной транзакцией и событием аудита. Команда не вводит публичную регистрацию.

Технические ключи API, значения ролей/статусов, адреса почты и введённые пользователем тексты сохраняют исходное значение. Бренды также сохраняются. Для произвольного HR-документа администратор должен предоставить и утвердить нужный перевод; приложение не выдаёт машинный перевод за официальный источник. Встроенный календарь браузера использует локаль самого браузера.

Исправлены два подтверждённых дефекта интерфейса: казахские даты отображались как `M10` в браузере с неполными данными локали; коды действий аудита оставались английскими. Теперь названия месяцев заданы явно, а действия аудита переводятся при отображении.

## Запуск и переменные окружения

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
export ENVIRONMENT=development
export DEMO_MODE=true
export DEMO_PASSWORD='Password123!'
export DATABASE_URL=sqlite:///./janamen-demo.db
export ACCESS_TOKEN_EXPIRE_MINUTES=60
export AI_CONFIDENCE_THRESHOLD=0.8
export ENABLE_MOCK_INTEGRATIONS=false
python -m app.migrate
python -m app.seed
python -m app.provision_demo
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

В локальной разработке ключ подписи может быть временным. Для постоянных сессий задайте случайный `SECRET_KEY` через окружение. Для промышленного окружения сильный ключ обязателен, демонстрационный режим запрещён. Полный перечень переменных — `.env.example`. Реальные секреты в репозиторий не добавлялись.

## API и схема

Действуют все прежние 35 путей / 38 операций: [полный список](ENDPOINTS.md), [контракт](API_CONTRACT.md), [OpenAPI](openapi.json), [13 таблиц и связи](../ARCHITECTURE.md). Новых публичных способов создавать пользователей нет.

```http
POST /api/v1/auth/login
Content-Type: application/json
Accept-Language: ru-RU

{"email":"employee.demo@example.com","password":"Password123!"}
```

Далее используйте `Authorization: Bearer <access_token>`. Смена языка:

```http
GET /api/v1/me/dashboard
Authorization: Bearer <access_token>
Accept-Language: kk-KZ
```

Пример ответа с источниками:

```http
POST /api/v1/ai/chat
Authorization: Bearer <access_token>
Content-Type: application/json
Accept-Language: kk-KZ

{"question":"Демалысқа өтінішті қалай беремін?"}
```

Открытие цитаты: `GET /api/v1/ai/sources/<chunk_id>?revision=<document_revision>&language=kk`. Значения берутся из ответа чата; авторизация и проверки доступа остаются обязательными. Правка источника без новых переводов очищает устаревшие переводы и снимает утверждение. Повторное утверждение требует текущей ревизии.

## Как проверить интерфейс

1. Откройте http://127.0.0.1:8765/ и обновите страницу. На экране входа выберите Русский или Қазақша.
2. Войдите как `employee.demo@example.com`. Проверьте профиль, уведомления, два курса; создайте заявку на доступные будущие даты в пределах баланса.
3. Выйдите либо выберите демо-руководителя в шапке. Войдите как `manager.demo@example.com`. Откройте команду и согласования: должна быть видна заявка его сотрудника. Согласуйте или отклоните её один раз.
4. Войдите как `hr.demo@example.com`. Откройте кадровое администрирование, документы и аудит. Для правки источника просмотрите полный текст и явно утвердите текущую ревизию.
5. В AI Jana нажмите вопрос о подаче отпуска, затем источник. Задайте вопрос о страховании домашних животных: ожидается сообщение об отсутствии утверждённого источника.
6. Поменяйте язык в шапке и проверьте обновление данных. Написанные ранее сообщения и процитированные источники сохраняют язык исходного ответа.

Остаются ограничения MVP: SQLite и один процесс для локальной демонстрации; поиск AI по словам без внешней языковой модели; нет промышленного SSO, восстановления пароля, архивирования старых тел источников и защиты аудита от администратора базы. 1С и Documentolog не подключены. Проверка браузера выполнена в macOS; другие ОС и Docker в этой сессии не запускались. Демо-данные не являются официальными кадровыми политиками.
