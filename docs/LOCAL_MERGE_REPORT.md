## Подтверждённые проблемы и исправления

1. PostgreSQL fixture выполняла `DROP SCHEMA public CASCADE`. Теперь каждый тест создаёт собственную случайную схему и удаляет только её в `finally`. Дополнительная проверка сохранила контрольную строку в `public`, оставшихся тестовых схем — 0.
2. Gemini мог возвращать произвольный выдуманный текст вместе с одной настоящей цитатой. Теперь весь отображаемый ответ должен состоять из точных цитат на языке интерфейса. Неизвестные, повторные и некорректно типизированные ID отклоняются без HTTP 500. Генерация не обходит пороги retrieval/ML.
3. Параллельные заявки могли одновременно занять одинаковые даты или превысить резерв доступных дней. Блокировка записи профиля до проверки сериализует создание. Тесты одновременных одинаковых и разных периодов прошли на SQLite и PostgreSQL.
4. Проверялось только начало периода: окончание в 9999 году попадало в дорогостоящий расчёт. Проверяются обе границы. Подсчёт исключений больше не перебирает каждый день периода.
5. Входящий календарь выдавался за официальное правило 1С. Теперь исключаются только явно настроенные `LEAVE_EXCLUDED_DATES`, по умолчанию список пуст. 1С и Documentolog остаются неподключёнными. Убраны ложные UI-подписи о получении профилей из 1С, внешней регистрации и искусственные внешние ID в генераторе.
6. История сотрудника загружалась целиком перед обрезкой; запросы ограничены до объединения. Устранены 11 ошибок mypy в новых модулях.
7. Переключение языка во время загрузки показывало ожидаемую отмену запроса как ошибку. Такие уведомления теперь подавляются; настоящие ошибки остаются видимыми.
8. На экране 319 px верхние кнопки и переключатели расширяли страницу до 383 px. Добавлен перенос элементов; фактическая ширина страницы теперь 319 px. Добавлены доступные названия кнопок помощи и выхода.
9. Сохранены SQLite и прежний Docker volume по умолчанию. PostgreSQL вынесен в явный альтернативный `docker-compose.postgres.yml`, без автоматического переноса или замены данных.

## Запуск и API

Приложение перезапущено: **http://127.0.0.1:8765/**. Используется прежняя временная демонстрационная БД с созданными ранее аккаунтами. Корневые `.env` и `janamen.db` не изменены (проверены SHA-256). Перед перезапуском сделана копия demo БД. Смена секрета локального процесса завершила старые сессии; нужно войти заново.

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
# Выберите DATABASE_URL и SECRET_KEY в собственном окружении.
python -m app.migrate
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Полные контракты: `docs/openapi.json`. Новое: `GET /api/v1/manager/team/{user_id}`; расширены `GET /manager/team`, ответы заявок (`vacation_days`) и AI (`engine`, `sources[].relevance`). Права берутся из серверной сессии.

```bash
curl http://127.0.0.1:8765/api/v1/manager/team \
  -H 'Authorization: Bearer <TOKEN>' -H 'Accept-Language: kk-KZ'
```

Переменные: существующие `SECRET_KEY`, `DATABASE_URL`, `DEMO_MODE`, `DEMO_PASSWORD`; новые необязательные `AI_PROVIDER`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_TIMEOUT_SECONDS`, `AI_RETRIEVAL_MODE`, `AI_RETRIEVAL_MODEL_PATH`, `MAX_ADVANCE_AMOUNT`, `REQUEST_HORIZON_DAYS`, `LEAVE_EXCLUDED_DATES`. Реальные секреты не записаны в отчёт или исходники. Для PostgreSQL compose — `POSTGRES_PASSWORD` и `POSTGRES_PORT`.

## Оставшиеся ограничения

- ML остаётся экспериментальным: на повторном наборе верны первые источники 8/16 отвечаемых вопросов; ещё 8 дают безопасный отказ. Test уже использовался раньше и не является новой независимой оценкой. Порог обученного reranker — 0.8; по умолчанию включён локальный поиск.
- Лексический privacy guard не заменяет полноценную классификацию/редактирование PII. Внешний AI выключен; перед включением требуется согласовать передачу вопроса и утверждённых источников провайдеру. Даже точная цитата не доказывает релевантность документа любому вопросу.
- Даты исключений и ограничения MVP должны быть настроены по утверждённым HR-правилам. Изменение календаря может изменить вычисление исторических дней: для production нужны сохранённая версия календаря и сумма списания на заявке.
- SQLite в PostgreSQL автоматически не мигрируется. Входящий `benchmark-postgresql.json` — прежний замер другой рабочей копии; его throughput не перепроверялся на текущем merge.
- API Gemini проверен только с mock-ответами и отказами. Справка контракта: https://ai.google.dev/api/generate-content .
