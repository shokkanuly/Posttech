# ML для поиска утверждённых HR-документов

Цель — выбрать подходящий источник. Модель не сочиняет ответы, не принимает кадровые решения и не обучается на личных записях сотрудников. Ответ Jana остаётся точной выдержкой из действующего утверждённого документа, доступного текущему пользователю.

## Файлы

| Путь | Назначение |
|---|---|
| `data/train.jsonl` | 58 синтетических примеров для обучения |
| `data/validation.jsonl` | 20 примеров для выбора порога |
| `data/test.jsonl` | 22 отложенных примера для итоговой оценки |
| `data/query.schema.json` | Схема вопроса, языка, роли, ожидаемого результата и правильных источников |
| `train.py` | Обучение LogisticRegression на парах «вопрос — раздел» |
| `evaluate.py` | Оценка сохранённой модели на отдельном наборе |
| `search.py` | Поиск по локальным синтетическим файлам без подключения к приложению |
| `reports/baseline.json` | Фактически полученные метрики, ошибки и хеши входных данных |
| `MODEL_CARD.md` | Возможности и ограничения модели |

Всего 100 примеров: по 50 на русском и казахском. Вопросы покрывают восемь тем, отсутствие источника, попытку отменить правила и приватные запросы. Две языковые версии одного смысла имеют общий `group_id` и всегда находятся в одном наборе. Валидатор запрещает пересечения групп, повторные вопросы и ссылки на недоступные источники.

Пример строки JSONL:

```json
{"id":"vacation-1-ru","group_id":"vacation-1","language":"ru","role":"employee","question":"Как подать заявку на отпуск?","expected_status":"grounded","relevant_source_ids":["demo-vacation:guide"],"synthetic":true}
```

Для `fallback` и `unauthorized` список правильных источников пустой. Содержимое ответов в разметку не придумывается: оно берётся из файлов `knowledge/documents/`.

## Запуск

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-ml.txt
python -m ml.validate
python -m ml.train
python -m ml.evaluate
python -m ml.search --language ru --question 'Как подать заявку на отпуск?'
python -m ml.search --language kk --question 'Демалысқа өтінішті қалай беремін?'
```

Обучение локальное. Внешний AI-сервис, API-ключ и платная инфраструктура не требуются. Артефакт `ml/artifacts/relevance.json` создаётся обучением и исключён из Git; данные и отчёт версионируются. Сохранены только числовые коэффициенты, порог, версия признаков и хеши наборов. Загрузка `pickle` или `joblib` не используется.

Обучение и проверки выполнены на Python 3.14 в macOS. Docker-образ включает файлы правил для штатного сервера; обучение вынесено в отдельное локальное окружение. Сборка Docker в этой проверке не запускалась.

Модель обучается на 366 парах и четырёх признаках: покрытие терминов вопроса, пересечение токенов, сходство символьных триграмм и покрытие заголовка. Порог выбирается только на validation с повышенным штрафом за неправильный принятый источник. Test используется для отчёта после выбора порога. Сохранённые JSON-коэффициенты проверяются на совпадение со значениями обученного классификатора.

## Подключение к приложению

По умолчанию работает прежний поиск `lexical`. Для экспериментального ранжирования после обучения задайте окружение **перед запуском нового процесса**:

```bash
export AI_RETRIEVAL_MODE=ml
export AI_RETRIEVAL_MODEL_PATH="$PWD/ml/artifacts/relevance.json"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Используйте нужный `DATABASE_URL`. Сами JSON-файлы не становятся утверждёнными источниками при обучении; их импорт и ручное утверждение описаны в [knowledge/README.md](../knowledge/README.md).

Сначала сервер отбирает действующие утверждённые разделы по роли и доступному языку. Сохраняется прежняя обязательная проверка покрытия терминов вопроса (`AI_CONFIDENCE_THRESHOLD`, по умолчанию 0.8). Только затем ML ранжирует кандидатов и проверяет свой порог. Недостаток свидетельств приводит к безопасному отказу. Если артефакт отсутствует или повреждён, используется прежний поиск; журнал содержит только класс ошибки, без вопроса, пути модели или кадрового текста.

`ml.search --role` моделирует роль только внутри синтетического локального корпуса. В HTTP API права всегда берутся из проверенной сессии, независимо от параметров модели.

## Фактическое качество

Первая версия на отложенном наборе из 22 вопросов правильно принимала источник для **2 из 16** вопросов с ответом. После добавления русских и казахских словоформ в токенизатор (метки сохранены; повторная регрессионная оценка, не новый независимый test) переобученная модель принимает **8 из 16** ([повторный запуск](reports/merge-evaluation.json), порог 0.8), все 8 принятых источников верны (precision 1.0). 4/4 вопроса без источника и 2/2 приватных запроса обработаны ожидаемо; остальные 8 вопросов с ответом получают безопасный отказ.

Поэтому модель оставлена **необязательной**. Для улучшения нужны дополнительные независимо размеченные перефразировки, обработка словоформ русского и казахского и новый нетронутый тестовый набор. Нельзя повышать метрику изменением тестовых меток или использовать результаты теста для подбора порога. Этот небольшой корпус показывает работоспособность конвейера и проверки безопасности.

## Проверки

```bash
python -m pytest -q tests/test_knowledge_files_and_ml.py
python -m pytest -q
python -m mypy app ml --check-untyped-defs
ruff check .
ruff format --check .
```

Тест обучения выполняется при установленном `requirements-ml.txt`; без необязательной зависимости он явно пропускается. Обычный сервер не импортирует scikit-learn и не требует ML-зависимостей для применения JSON-модели.

Техническая справка: [LogisticRegression](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html), [безопасность сохранения моделей](https://scikit-learn.org/stable/model_persistence.html).
